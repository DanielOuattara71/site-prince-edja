# AGENTS.md — Prince Edja

## Stack
Vite 8 + React 19 + TypeScript ~6.0 (strict) + Tailwind CSS v4 (`@tailwindcss/vite`) + Motion (`motion/react`) + React Router 7. Fonts self-hosted via `@fontsource`. Package manager: **npm** (`package-lock.json`).

## Commands
```bash
npm install
npm run dev          # vite dev server
npm run build        # tsc -b && vite build  (typecheck is part of build)
npm run preview      # preview dist/
npm run lint         # oxlint (not eslint)
npm run typecheck    # tsc -b (project references)
npm run seo:check    # compare public/sitemap.xml aux routes réelles
```
Verification order (from README): `npm run typecheck && npm run lint && npm run build`

CI : **un** workflow, `.github/workflows/deploy.yml` — push sur `recent` (et `workflow_dispatch`) → **GitHub Pages**, pas Vercel. Il enchaîne `npm run seo:check` **puis** `npm run build`. Ni `lint` ni `typecheck` séparé (le build fait déjà `tsc -b`). Conséquence : un sitemap oubliant une route casse le déploiement ; un `oxlint` qui gémit, non. No tests, no pre-commit hooks.

## Project References & Types
- `tsconfig.json` is reference-only → `tsconfig.app.json` (`src/`) + `tsconfig.node.json` (`vite.config.ts`).
- Strict flags: `noUnusedLocals`, `noUnusedParameters`, `erasableSyntaxOnly`, `verbatimModuleSyntax`, `allowImportingTsExtensions`, `moduleDetection: force`. Unused vars/params fail typecheck; use `import type` for types.
- Path alias `@/*` → `src/*` (defined in `vite.config.ts:10` and `tsconfig.app.json:12`). Always use `@/` for src imports.

## Architecture
- Entrypoints: `src/main.tsx` → `src/App.tsx`. `BrowserRouter basename="/site-prince-edja"` (base GitHub Pages) ; `vercel.json:3` porte la réécriture SPA — inutile pour la CI, utile seulement si le site est aussi servi par Vercel. Les `<loc>` du sitemap portent la base GitHub Pages.
- Routes (`src/App.tsx:104-180`) : `/`, `/a-propos`, `/xplore`, `/xplore/:slug`, `/taste-and-travel`, `/journal`, `/presse`, `/contact`, `*` (404). Le marché est un nid `<Route element={<MarcheLayout />}>` : `/boutique`, `/boutique/:comptoir`, `/boutique/:comptoir/:piece`, `/ma-demande` — le dock et le tiroir de sélection y sont montés **une seule fois**, d'où la survie du plan de comptoirs à la navigation. Home eager, tout le reste `lazy()`.
- Layout: `SiteLayout` wraps Header/Footer/`LoaderIntro`/`AnimatedOutlet` (motion page transitions, respects `useReducedMotion`).
- Content is data-driven: all copy lives in `src/data/*.ts` (`content.ts`, `site.ts`, `gallery.ts`) typed by `src/types/index.ts`. Components must not hardcode text — edit data files instead.
- Styling: Tailwind v4 theme & custom utilities in `src/styles/globals.css` (`@theme`, `@utility`). No `tailwind.config.js`.
- Motion constants: `src/lib/motion.ts` (`DUR`, `EASE_EXPO`, `EASE_QUART`, `fadeUp`, `staggerContainer`). Import from `motion/react`.
- SEO : `src/hooks/useSeo.ts` est le seul point d'écriture des balises. À chaque navigation il pose `title`, `description`, `robots` (`indexable: false` → `noindex, follow`, utilisé par `/ma-demande`), `og:title`/`og:description`/`og:url`/`og:image` en **absolu**, et un `<link rel="canonical">` sans requête ni ancre. Ne pas dupliquer cette écriture dans un composant. Le `sitemap.xml` est généré/vérifié par `scripts/seo.mjs` (`npm run seo` / `seo:check`).
- Helpers: `src/lib/cn.ts` (`clsx` + `tailwind-merge`), `src/lib/format.ts`.

## Lint / Format
- Linter: **oxlint** with `react`, `typescript`, `oxc` plugins (`.oxlintrc.json`). Rules: `react/rules-of-hooks: error`, `react/only-export-components: warn (allowConstantExport)`.
- Formatter: Prettier (`printWidth: 100`, `singleQuote: true`, `trailingComma: all`) — no npm script, run via editor/npx if needed.

## Env & Assets
- Env var: `VITE_WEB3FORMS_ACCESS_KEY` (see `.env.example`). Local env files are gitignored (`.env`, `.env.local`).
- Images: placeholders in `public/images/` generated by `scripts/placeholders.mjs` (uses `sharp` — not in deps, `npm i -D sharp` if needed). Production expects AVIF/WebP + mp4 ≤3 MB with poster; OG image at `/images/og-prince-edja.jpg` referenced in `index.html:21`.

## Contrat de direction artistique

Règles issues de l'analyse de DA (sept. 2026). Elles existent pour qu'un comptoir ajouté
dans six mois ressemble encore aux cinq autres.

**Voix typographiques** — quatre rôles, jamais cinq :
- `font-display` (Anton) = la voix du brand : titres de section, chiffres, bandeaux.
- `font-title` (Fraunces) = la voix de la pièce : nom d'un produit, intention d'un comptoir, récit.
- `font-sans` (Manrope) = la voix du service : corps, labels, boutons.
- `font-data` (monospace) = la voix du chiffre : prix FCFA, références, compteurs, `12/30`. Utiliser l'utilitaire `data-mono`.

**Couleur**
- L'or (`gold-*`) est un matériau, pas une couleur de texte : filets, puces, halos, numéros ≥ 24 px. `gold-400` sur `sand-50` ≈ 2,1:1 → interdit en texte.
- Sur fond clair, un label secondaire est en `ink-500`, jamais en or ni en `clay-500` (≈ 3,7:1).
- `leaf-500` sur `forest-950` ≈ 3,0:1 → en remplissage seulement ; le texte sur forêt est en `cream-100`/`sage-200`.

**Rayons** — quatre tokens, aucune valeur arbitraire (`rounded-[9rem]` et compagnie sont à proscrire) :
- `rounded-sharp` (3px) = action marchande et visuel produit.
- `rounded-soft` (14px) = blocs.
- `rounded-feature` (28px) = visuel vedette, **une fois par écran**.
- `rounded-pill` = navigation, pastilles, dock. Jamais sur un produit.

**Mouvement**
- Trois durées : `--d-fast` 200 ms (feedback), `--d-base` 450 ms (changement d'état), `--d-reveal` 750–800 ms (révélation).
- Une seule chorégraphie scénique par viewport. Les Chapiteaux de comptoir : ~110 vh pour le comptoir actif, ~50 vh pour les suivants.
- Une seule boucle d'animation par page : le chrome global (`SiteChrome`) est le seul endroit où l'on ouvre un `requestAnimationFrame`.
- `SectionMarker` est **le** marqueur de section : trait capillaire qui se trace + étiquette qui glisse dans son masque. Tout bloc qui annonce une section l'utilise. `Eyebrow` a été supprimé (migré sur 12 fichiers) : deux langages d'annonce, c'est deux langages de mouvement. Un formulaire n'est pas une section — il garde un `label-caps` nu.
- **Le décor bouge, la marchandise est fixe** : un visuel produit passe par `MediaFrame` (aucune parallaxe), jamais par `ParallaxImage`. `ParallaxImage` reste **correct** sur l'éditorial (Hero, films, villes, galerie) : ce sont des décors, pas des produits. Le compte de fichiers qui l'utilisent n'est donc pas un défaut.
- **Aucune brique morte.** Une utility ou une keyframe qui n'est appelée nulle part est retirée, pas laissée « pour plus tard » : `band-grid` et `pe-iris` ont été supprimées, la variante courte du Chapiteau aussi. `pe-stamp` a été branchée sur le tampon d'édition de la fiche produit. Seule exception admise : les jetons d'une **échelle** (`--radius-feature`) — une échelle peut avoir un cran non encore utilisé.
- Cascades : utiliser `delaiCyclique` (`src/lib/motion.ts`), qui recycle le délai tous les 4 éléments.
- `prefers-reduced-motion` coupe boucles, autoplay et chapiteaux, remplace les révélations par un état posé, **conserve** les 200 ms de feedback. Ne pas masquer les matières statiques (grain, filets) au motif qu'elles seraient « animées » : le grain est une texture, il reste.
- Le halo de pointeur est en `mix-blend-screen` : le `multiply` d'origine rendait le halo invisible sur les sols nuit, la moitié du site.
- **Glisser = Pointer Events, jamais `onMouse*`** : les événements souris ne se déclenchent pas au doigt. Capturer le pointeur (`setPointerCapture`) pour garder le suivi 1:1 hors de la carte, et laisser `touch-pan-y` passer le défilement vertical — sinon on piège le scroll sur mobile. La valeur du drag pendant le geste se lit dans une `ref`, pas dans l'état : dans une closure, c'est la valeur du rendu précédent et le seuil d'accroche part d'un cran en retard.

**Marché**
- Vocabulaire : *pièce*, *comptoir*, *atelier*, *édition*, *provenance*. Pas *article*, pas *produit*, pas *shopping*.
- Pas de paiement en ligne : on **réserve** une pièce, on envoie une **demande**. Écrire `Option posée · réponse sous 24 h`, jamais `Réservé` sans cette limite.
- Les jetons d'univers s'écrivent `var(--c-*)` et ne sont lus que par les briques de `src/components/market/`. Un composant du site éditorial ne doit jamais dépendre de `--c-*`.
- Tout symbole culturel (Adinkra et consorts) est un signe à signification : l'association symbole ↔ catégorie exige une validation humaine avant mise en ligne.
- **Une seule identité.** Trois marques coexistaient (un « P » abstrait en favicon, un masque dans le seul loader, un mot-marque + point or dans l'en-tête). Le favicon et `Embleme` (`src/components/brand/`) portent désormais **la même géométrie**, en deux échelles : détaillée dans le loader, réduite ailleurs. ⚠️ `public/favicon.svg` et `Embleme.tsx` doivent rester synchrones. Le mot-marque du header ne porte plus de point or : doublon avec l'accent.
- **Les prix vivent uniquement dans `src/data/produits.ts`**, lus par `marche(slug)`. Aucun composant ne porte de montant en dur. Les montants actuels sont des **mock** (`prixConfirme: false` → l'interface affiche « Prix indicatif »). Le backend remplacera `PRODUITS`, la forme ne bougera pas.
- **Atelier, village, poids, matières : `null` tant qu'ils ne sont pas fournis et vérifiés.** Une provenance inventée sur une fiche produit publiée engage la maison : on ne comble pas un champ de crédibilité avec du plausible.

## Gotchas
- `npm run build` déjà `tsc -b` ; un `typecheck` séparé sert au retour rapide.
- `@utility` ne peut **pas** être imbriqué dans Tailwind v4 : les utilitaires du projet sont au racine de `globals.css`, et un `@utility` mal fermé casse le build entier.
- `gold-400` sur fond clair et `leaf-500` sur forêt échouent au contraste WCAG : ne pas les employer en texte.
- `ink-400` sur `sand-50` = **4,06:1**, sous le seuil AA : un label secondaire sur fond clair est en `ink-500` (4,77:1). Balayé dans `PriceTag`, `Cartel`, `DemandePage`.
- L'anneau `:focus-visible` est un repère **non-texte** : il lui faut 3:1. `leaf-600` ne rend que 2,5:1 sur `night-900` et 2,0:1 sur `kola-900` — la règle de `globals.css` lit donc `var(--c-accent, var(--color-nature))`. Sur un sol sombre, mesurer l'anneau aussi, pas seulement le texte.
- Échelle typographique = 8 tokens (`display-xl`, `display-lg`, `heading-md`, `heading-sm`, `body-lg`, `body`, `caption`, `button`). `text-body-sm` et `text-heading-xs` **n'existent pas** : aucune règle n'est émise, la taille retombe sur l'héritée, et le build ne dit rien.
- Le marché n'a pas d'inventaire par comptoir : `ComptoirPage` affiche `BIJOUX` entier dès que `nbPieces > 0`, et `piecesDemo()` uniquement en régie rail. Un comptoir avec un vrai inventaire **et** une régie rail afficherait un rail vide — à traiter à l'ouverture d'un deuxième comptoir réel.
- Un fichier de `public/` s'écrit **toujours** `` `${import.meta.env.BASE_URL}chemin` `` : `vite.config.ts` fixe `base: '/site-prince-edja/'`, donc un `"/motifs/x.svg"` en dur sort du déploiement et le visuel ne charge ni au dev ni en prod (c'était le cas des quatre motifs de chapiteau). Dans `index.html`, Vite préfixe seul le `href`/`content` — ne pas toucher.
- Sous WSL, les assets touchés depuis Windows basculent en `100755` : 34 PNG du `public/` apparaissaient « modifiés » pour un simple bit exécutable. `git config core.fileMode false` (déjà posé ici) supprime le bruit ; sans ça, le commit embarque 34 changements de permission.
- Branche réellement vérifiée sur le dépôt : `recent`. `admin/config.yml` (Decap) vise `version_3` **et** un repo `prince-edja/site` qui n'existe pas → à réaligner avant toute édition de contenu.
- Trois interfaces d'administration coexistent (`src/pages/admin`, `admin/`, `admin-custom/`) : ne pas y ajouter de données de marketplace avant d'avoir tranché la source de vérité.
- `dist/` est la sortie de build (gitignored).
